# Newsletter Digest & Trends Dashboard — How It's Set Up

Last verified: 2026-09-21.

## What it does

Twice a week, a job on this Mac reads the last three days of Gmail, picks out
tech and legal-tech newsletters, pulls a set of RSS feeds, has Claude write a
digest, emails it, and extracts structured trend data that a public GitHub
Pages dashboard charts.

```
launchd (Wed/Fri 08:00)
  └─ ~/Library/Application Support/newsletter-digest/run.sh
       ├─ brctl download  (pull iCloud-evicted files back to disk)
       ├─ ANTHROPIC_API_KEY  <- login Keychain
       └─ ~/Library/Application Support/newsletter-digest/.venv/bin/python main.py
            ├─ gmail_client.py        Gmail API, last 3 days, up to 200 messages
            ├─ newsletter_detector.py sender whitelist + keyword match (config.yaml)
            ├─ rss_fetcher.py         9 feeds (config.yaml)
            ├─ summarizer.py          Claude -> digest markdown
            ├─ digest_formatter.py    markdown -> HTML email -> Gmail send
            ├─ trend_extractor.py     Claude -> trends-dashboard/data/digest-<week>.json
            └─ push_dashboard_data()  git add/commit/push trends-dashboard/data/
                                        │
GitHub Pages (from main) ───────────────┘
  https://rbpasternak-tech.github.io/bexperiments/trends-dashboard/
    index.html + js/data-loader.js reads data/index.json, loads the 24 newest digests
```

## Where things live

| Thing | Path | Why there |
|---|---|---|
| Source code and config | `~/Documents/GitHub/bexperiments/newsletter-digest/` (also reachable as `~/bexperiments`, a symlink) | The repo |
| Python venv | `~/Library/Application Support/newsletter-digest/.venv` | Outside iCloud, see below |
| launchd runner | `~/Library/Application Support/newsletter-digest/run.sh` | Outside iCloud, generated by the installer |
| launchd job | `~/Library/LaunchAgents/com.bexperiments.newsletter-digest.plist` | Standard user-agent location |
| Log | `~/Library/Logs/newsletter-digest/digest.log` | Outside iCloud and outside `/tmp`, which macOS purges |
| Anthropic key | Login Keychain, service `newsletter-digest-anthropic` | Never in a file |
| Gmail OAuth client | `newsletter-digest/credentials.json` | Gitignored |
| Gmail refresh token | `newsletter-digest/token.json` | Gitignored, rewritten on refresh |
| Dashboard data | `trends-dashboard/data/` | Committed and pushed by the job |

## The iCloud problem

`~/Documents` is synced by iCloud with "Optimize Mac Storage" on. iCloud
evicts idle files to zero-byte "dataless" placeholders. An interactive
Terminal process can read one transparently, because macOS downloads it on
demand. A launchd-spawned process cannot, and the read fails with
`OSError: [Errno 11] Resource deadlock avoided`.

This is why the digest silently stopped after Aug 28, 2026. The old job pointed
at a venv inside the repo, iCloud had evicted 5,224 of its 5,225 files, and
Python died in its own startup before `main.py` ran. The stdout log was never
even created.

The setup avoids this three ways:

1. The venv, the runner script and the log live under `~/Library`, which iCloud
   does not sync.
2. The runner calls `brctl download` on the project directory and waits until
   `config.yaml`, `credentials.json` and `token.json` are real files before
   starting Python.
3. Nothing launchd needs at spawn time is inside the repo.

The agent-team bot uses the same pattern, and its installer was the template.

## Setting it up from scratch

1. **Gmail API client.** In Google Cloud Console, enable the Gmail API and
   create an OAuth client ID of type Desktop app. Download the JSON as
   `credentials.json` into this folder.
2. **Anthropic key in Keychain.**

   ```bash
   security add-generic-password -a "$USER" -s newsletter-digest-anthropic \
       -l "newsletter-digest Anthropic API key" -w "<your key>" -U
   ```

   The same command with `-U` replaces the value later. The runner picks it up
   on the next run with no reinstall.
3. **Install the job.**

   ```bash
   cd ~/Documents/GitHub/bexperiments/newsletter-digest
   ./install-launchd.sh
   ```

   This creates the venv if missing, refuses to continue if the Keychain item
   or `credentials.json` is absent, generates the runner, writes the plist,
   and loads it. Re-run it any time to replace the job.
4. **First run does Gmail OAuth.** Run through the wrapper once from a
   Terminal so the consent window can open, and `token.json` gets written:

   ```bash
   ~/Library/Application\ Support/newsletter-digest/run.sh --dry-run --skip-trends
   ```

## Day to day

| Task | Command |
|---|---|
| Check the job is loaded | `launchctl print gui/$(id -u)/com.bexperiments.newsletter-digest \| grep -E 'state\|last exit'` |
| Run it now, exactly as scheduled | `launchctl kickstart gui/$(id -u)/com.bexperiments.newsletter-digest` |
| Watch the log | `tail -f ~/Library/Logs/newsletter-digest/digest.log` |
| Preview without emailing or pushing | `~/Library/Application\ Support/newsletter-digest/run.sh --dry-run --skip-trends` |
| Backfill a past week's trend data | `... run.sh --backfill <see main.py --help>` |
| Uninstall | `launchctl bootout gui/$(id -u)/com.bexperiments.newsletter-digest && rm ~/Library/LaunchAgents/com.bexperiments.newsletter-digest.plist` |

`--dry-run` alone still extracts trends and pushes them to GitHub. Add
`--skip-trends` when you want zero side effects.

## Things that bit us

- **The job pushes to whatever branch is checked out.** `push_dashboard_data()`
  runs plain `git push` in the repo. Pages builds from `main`, so if the repo
  is sitting on a feature branch, the data lands there and the live dashboard
  never sees it. Keep `main` checked out, or merge before Wed/Fri 08:00.
- **The dashboard was frozen at July 10 for two months.** `index.json` lists
  digests oldest first and `data-loader.js` kept the first 24, so once there
  were more than 24 digests the newest were dropped. Fixed on 2026-09-21 to
  sort newest first before capping. If the dashboard ever shows a stale date
  again, check this before anything else.
- **The old plist had the API key in plaintext.** The installer never writes
  the key anywhere; it is read from Keychain at run time.
- **`/tmp` logs disappear.** macOS deletes files in `/tmp` after a few days
  idle, which hid the earlier failure. Logs now live in `~/Library/Logs`.
- **Two harmless `getcwd: Operation not permitted` lines** appear at the top
  of each log. launchd starts the shell inside the iCloud folder before the
  runner does its own `cd`. Ignore them.
- **Stale browser view.** The dashboard caches loaded data in `localStorage`
  keyed on `index.json`'s `last_updated`. A normal reload after a new run is
  enough; if not, Cmd+Shift+R, or in the console
  `localStorage.removeItem('dashboard-data-cache')`.

## Public exposure

The repo and the Pages site are public. Credentials and tokens are
gitignored and have never been committed. The trend data files are public and
contain newsletter summaries, source names and sender addresses from your
inbox.
